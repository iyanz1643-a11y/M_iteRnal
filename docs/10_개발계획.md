# 10. 개발 계획

2026년 11월 14일 기준이다. 기능의 상세는 `09_기능기획서.md`, 도구와 구조는 `11_개발구조.md`, AI가 일하는 방식과 에이전트는 `13_AI운영설계.md` 에 있다. 열린 결정은 이 문서의 7장 한 곳에만 둔다.

## 1. 앱 정의와 범위

이터널총괄본부가 보험 계약과 실적을 관리하고, 관리자가 조직의 교육과 진척을 챙기며, 설계사가 자기 진척과 진행 중인 프로모션을 보고 고객 제안까지 이어 가는 업무 앱이다.

| 쓰임 | 내용 |
| --- | --- |
| 관리 | 계약, 실적, 수수료, 시상을 적재하고 점검하고 마감한다 |
| 육성 | 교육 진척도, 커리어패스, 인증, 프로모션 달성 현황을 사람별로 본다 |
| 제안 | DB 배정에서 보장분석 제안 리포트, 카드뉴스, 모바일 명함까지 잇는다 |

하지 않는 것은 세 가지다. 원수사 전산이나 본사 정산 시스템을 대신하지 않는다. 수수료와 시상금을 지급하지 않는다. 공식 광고 심의를 대신하지 않는다.

## 2. 사람과 역할

| 누구 | 역할 | 하는 일 |
| --- | --- | --- |
| 대표님 | 메인 관리자, 결정과 결재 | 다섯 가지 검토 사항의 결정, 운영 배포와 밖으로 나가는 일의 승인 |
| AI 총괄 | 개발 루프를 돌리는 메인 작업 | 파트를 고르고 에이전트에게 나눠 맡기고 합쳐서 보고 |
| AI 에이전트 9개 | 파트별 실무 | 데이터, 계산, 화면·랜딩, 기반·권한, 백엔드·인프라, 연결, 앱 AI, 검증, 문서. 상세는 `13_AI운영설계.md` 4장 |

앱을 쓰는 사람은 메인 관리자, 관리자(지사장·본부장, 지점장, 팀장), 설계사의 세 역할이다. 조직은 GA, 지사 또는 본부, 지점, 센터, 팀, 설계사의 순서다. 센터는 D-01 에서 확인한다.

### 6.2 프론트엔드

- 서버에서 화면을 그리고 자바스크립트는 최소로 쓴다. 혼자 운영하기 쉽기 때문이다.
- S2에 휴대폰 홈 화면 추가를 넣는다. 앱 정보 파일, 아이콘, 오프라인 안내다. S3에 푸시 알림을 넣는다.
- 디자인은 `12_디자인.md` 를 따른다. 화면 문구와 접근성 점검을 검증에 넣는다.

### 6.3 백엔드

| 항목 | 지금 | 목표 | 스프린트 |
| --- | --- | --- | --- |

### 6.4 인프라와 배포

- 컨테이너 하나, 관리형 PostgreSQL, 객체 저장소, 도메인과 HTTPS 로 구성한다. 서버 위치와 비용은 D-14 다.
- 시험용과 운영용 두 환경을 둔다.
- 올릴 때마다 자동 시험, 코드 점검, 컨텍스트 점검을 돌리고 통과하면 시험용에 배포한다. 운영 배포는 대표님 승인 뒤에 한다.
- 매일 백업하고 되살리기를 시험한다. 백업은 암호화한다.

### 6.5 연결

드라이브, 노션, 모바일 명함, Claude API, 카카오의 단계와 실패 대비는 `13_AI운영설계.md` 3장에 있다. 명함 연동은 S2의 1차와 2차, S3의 3차로 나눈다.
