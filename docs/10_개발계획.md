# 10. 앱 개요와 개발 계획

2026년 11월 13일 기준이다. 기능의 상세는 `09_기능기획서.md` 에 있다.

## 1. 앱 정의와 범위

이터널총괄본부가 보험 계약과 실적을 관리하고, 관리자가 조직의 교육과 진척을 챙기며, 설계사가 자기 진척과 진행 중인 프로모션을 보고 고객 제안까지 이어 가는 업무 앱이다.

| 쓰임 | 내용 |
| --- | --- |
| 관리 | 계약, 실적, 수수료, 시상을 적재하고 점검하고 마감한다 |
| 육성 | 교육 진척도, 커리어패스, 인증, 프로모션 달성 현황을 사람별로 본다 |
| 제안 | DB 배정에서 보장분석 제안 리포트, 카드뉴스, 모바일 명함까지 잇는다 |

| 단계 | 쓸 수 있게 되는 것 | 쓰는 사람 |
| --- | --- | --- |
| 1단계 운영 기반 | 로그인과 권한, 실제 조직, 실제 파일 적재, 실적과 랭킹, 시상안 원장 | 메인 관리자 |
| 2단계 사람별 화면 | 설계사의 내 진척과 프로모션, 관리자의 조직 실적과 교육 진척도 | 관리자, 설계사 |
| 3단계 제도와 제안 | 수수료 점검과 마감, 조직별 설정, 커리어패스, DB와 고객, 제안 리포트, 카드뉴스, 심사 | 전원 |

하지 않는 것은 세 가지다. 원수사 전산이나 본사 정산 시스템을 대신하지 않는다. 수수료와 시상금을 지급하지 않는다. 공식 광고 심의를 대신하지 않는다.

## 2. 페르소나

| 페르소나 | 누구 | 앱에서 이루려는 것 | 보는 범위 | 주 기기 |
| --- | --- | --- | --- | --- |
| 메인 관리자 | 운영 총괄 1인 | 자료를 올리고 점검하고 마감한다. 시상안과 제도를 승인하고 조직과 권한을 세팅한다 | 전체 | PC |
| 관리자 | 지사장·본부장, 지점장, 팀장 | 자기 조직의 실적과 교육 진척도, 팀원의 프로모션 달성 현황을 관리한다 | 자기 조직과 그 아래 | PC와 휴대폰 |
| 설계사 | 소속 설계사 | 내 실적과 시상 진척, 진행 중인 프로모션, 커리어패스 목표, 교육 수료를 챙기고 고객 제안 자료를 만든다 | 본인 | 휴대폰 |

조직 계층은 GA, 지사 또는 본부, 지점, 팀, 설계사의 다섯 단계다.

## 4. 파트별 업무

| 파트 | 만드는 것 | 스스로 확인하는 완료 기준 | 단계 |
| --- | --- | --- | --- |
| A. 기반 | 로그인, 세 역할의 권한, 조직 다섯 계층, 변경 기록 | 역할별 계정으로 들어가 범위 밖 자료가 보이지 않음을 자동 시험으로 확인 | 1 |
| B. 데이터 적재 | 실제 계약현황과 사원현황 양식의 매핑, 시상안 원본 읽기, 중복과 품질 검사 | 실제 한 달 치가 오류 없이 들어가고 건수와 합계가 원본과 일치 | 1 |
| C. 실적과 랭킹 | 월·분기·반기 업적, 업권 조건과 조직 범위가 걸린 랭킹 | 원본 엑셀의 합계와 일치. 인정업적 부문과 손해보험 건수 부문 순위가 나옴 | 1 |
| D. 프로모션 | 시상안 원장을 설계사용 프로모션으로 바꾸기, 내 달성 현황, 조직 부문 시상 | 승인한 시상안이 기간에 맞춰 뜨고, 표본 설계사의 달성액을 손계산과 대조 | 2 |
| E. 교육 | 과정과 차수, 수료 기록, 사람별·조직별 진척도 | 수료자 명부를 올리면 진척도가 맞게 계산됨 | 2 |
| F. 사람별 화면 | 역할별 홈, 내 진척, 관리자의 팀원 보기, 휴대폰 화면, 알림함 | 세 역할의 주요 화면을 실제 브라우저로 열어 오류와 깨짐이 없음 | 2 |
| G. 수수료와 점검 | 수수료와 환수 점검, 정산서 대사, 조정, 월 마감 | 일부러 넣은 차이를 모두 찾아냄. 마감 후 수정이 막힘 | 3 |
| H. 조직별 설정 | 조직이 물려받고 고쳐 쓰는 설정, 적용 시작 월, 변경 이력 | 아래 조직이 본사 잠금을 풀 수 없음. 지난 달 결과가 바뀌지 않음 | 3 |
| I. 제도 | 커리어패스의 기준·선발·시상, 인증과 임원제도 | 기준 버전을 바꿔도 지난 회차 결과가 유지됨 | 3 |
| J. 영업과 제안 | DB 배정과 성과, 고객관리, 보장분석 제안 리포트, 카드뉴스, 명함 연동 | 배정에서 리포트까지 한 건이 끊기지 않고 이어짐 | 3 |
| K. 심사와 운영 | 7나이츠 심사함, 운영 배포, 백업, 사용 안내 | 백업에서 되살리기 시험 통과. 심사 3회전 제한 동작 | 3 |

순서는 이렇다. A와 B를 먼저 한다. C, D, E는 B가 끝나면 나란히 간다. F는 그 결과를 사람별로 보여 주는 일이라 뒤에 온다. G, H, I는 서로 독립이다. J와 K는 개인정보와 외부 연결이 걸려 있어 마지막에 둔다.

## 5. 검토 방식

만드는 일은 스스로 진행하고, 다음 다섯 가지에 닿을 때만 검토를 받는다.

| 종류 | 예 |
| --- | --- |
| 돈 | 수수료와 시상 금액을 어떤 기준으로 계산하는가 |
| 사람 | 누가 무엇을 볼 수 있는가, 개인정보를 어디까지 담는가 |
| 제도 | 선발과 시상, 승격, 교육 수료의 기준 |
| 밖으로 나가는 것 | 고객에게 가는 리포트, 게시물, 설계사에게 가는 공지 |
| 되돌리기 어려운 것 | 운영 배포, 실제 자료의 삭제와 이관, 비용이 생기는 선택 |

- 화면 배치와 문구, 테이블 구조, 파일 해석 규칙, 샘플 데이터, 시험 방법, 나중에 바꿀 수 있는 기술 선택은 묻지 않고 정하고 문서에 남긴다.
- 물을 때는 질문 한 줄, 제안, 다른 선택지, 미루면 생기는 일의 네 줄로 묻는다.
- 답이 늦으면 제안대로 샘플 자료 안에서만 진행하고 가정으로 표시한다.
- 보고는 파트가 끝날 때 한 번 한다.
