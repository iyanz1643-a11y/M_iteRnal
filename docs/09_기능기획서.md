# 09. 기능 기획서

2026년 11월 13일 기준 초안이다. 범위와 개발 순서는 `10_개발계획.md`, 계산과 적재의 상세는 01~08 문서에 있다.

## 1. 목표와 성공 기준

이터널총괄본부가 보험 계약과 실적을 관리하고, 관리자가 조직의 교육과 진척을 챙기며, 설계사가 자기 진척과 진행 중인 프로모션을 보고 고객 제안까지 이어 가는 업무 앱이다.

| 목표 | 뜻 |
| --- | --- |
| 한 곳에서 본다 | 계약, 실적, 시상, 교육이 엑셀과 메신저에 흩어지지 않고 한 화면에 모인다 |
| 스스로 챙긴다 | 설계사는 자기 진척과 프로모션을, 관리자는 팀원 상태를 묻지 않고 안다 |
| 제안까지 잇는다 | 배정받은 DB가 상담, 보장분석, 제안 리포트로 끊기지 않고 이어진다 |

| 성공 기준 | 재는 방법 |
| --- | --- |
| 월 마감 소요 시간 | 그 달 첫 자료 적재부터 마감 잠금까지 걸린 날 |
| 시상안 게시 소요 시간 | 시상안을 받은 날부터 프로모션 게시까지 걸린 시간 |
| 설계사 주간 접속률 | 주 1회 이상 접속한 설계사의 비율 |
| 프로모션 열람률 | 게시된 프로모션을 연 설계사의 비율 |
| 교육 수료율 | 필수 과정 대상자 가운데 수료한 비율 |
| 마감 시점 미해결 차이 | 마감할 때 남은 대사 차이 건수 |
| 13회차 유지율 | 유지율 집계 |

목표값은 첫 달에 기준선을 잰 뒤 정한다.

## 2. 조직과 권한

### 2.1 조직 계층

11월 13일에 확정한 구조다.

| 계층 | 조직장 | 시상안의 표기 |
| --- | --- | --- |
| GA | 없음 | GA |
| 지사 또는 본부 | 지사장, 본부장 | 총괄, 지사 |
| 지점 | 지점장 | 없음 |

- 지사와 본부는 같은 계층이다. 이터널총괄본부는 이 계층의 한 조직으로 보았다. 12장에서 확인받는다.
- 한 조직은 상위 조직 하나에 속한다. 지점 없이 팀이 지사 바로 아래 붙는 경우도 받아들인다.
- 조직 개편과 인사 이동은 날짜와 함께 이력으로 남긴다. 실적은 계약 시점의 소속에 귀속한다.

### 2.3 권한 원칙

1. **조직 범위**: 자기 조직과 그 아래만 본다. 검사는 화면이 아니라 서버에서 한다.
2. **금액**: 수수료와 시상 금액은 본인과 메인 관리자만 본다. 조직 관리자는 실적과 달성 여부까지 본다. 12장에서 확인받는다.
3. **고객 개인정보**: 담당 설계사와 직속 조직 관리자만 본다. 메인 관리자는 조회 사유를 남기고 본다.
4. **순위**: 설계사에게는 상위 10명과 본인 순위만 보여 준다.
5. **쓰기**: 기준, 규칙, 승인, 마감은 메인 관리자만 한다. 조직 관리자는 자기 조직의 설정, 교육 수료 확인, DB 배정을 한다.
6. **기록**: 승인, 설정 변경, 내려받기, 범위 밖 접근 시도는 모두 남긴다.

## 3. 핵심 흐름

### 3.1 월간 운영 순환

| 시점 | 메인 관리자가 하는 일 | 앱이 하는 일 |
| --- | --- | --- |
| 월초 | 보험사별 시상안을 올린다 | 원장에 쌓고 해석 초안을 만든다. 확인이 필요한 줄을 표시한다 |
| 월초 | 해석을 확인하고 승인한다 | 승인한 줄을 프로모션으로 게시하고 대상 설계사에게 알린다 |
| 매주 | 본부 계약 엑셀을 올린다 | 청약과 철회를 거르고 실적과 프로모션 달성 현황을 갱신한다 |
| 수시 | 사원현황과 수료자 명부를 올린다 | 조직, 인사 이동, 교육 진척도를 갱신한다 |
| 월말 | 품질 경고와 대사 차이를 정리한다 | 차이 목록과 조정 기록을 남긴다 |
| 월말 | 마감한다 | 그 달을 잠그고 순위를 확정한다 |
| 익월 초 | 순위와 부문 시상을 공유한다 | 명예의전당에 게시하고 수상자에게 알린다 |
| 13회차 도래 | 유지 여부를 확인한다 | 13회차 지급 예정분과 환수 위험 계약을 목록으로 낸다 |

### 3.2 설계사의 한 주

1. 홈에서 이번 주에 마감되는 프로모션과 구간까지 남은 금액을 본다.
2. 배정받은 DB의 통화 결과를 기록하고, 상담한 고객의 보장분석 제안 리포트를 만든다.
3. 계약 뒤 자료가 적재되면 실적과 달성 현황에 반영된 것을 확인한다.
4. 교육 수료와 커리어패스 목표를 확인한다.

### 3.3 관리자의 한 주

1. 조직 홈에서 실적과 가동 인원을 본다.
2. 구간에 근접한 팀원 목록을 보고 독려한다.
3. 교육 미수료자를 확인하고 수료를 확인 처리한다.
4. DB를 배정하고 방치된 DB를 회수한다.
5. 면담 내용을 기록한다.

### 3.4 자료의 기준 시각

실적은 실시간이 아니고 계약 엑셀을 올린 시점 기준이다. 모든 실적 화면에 마지막 적재 시각을 표시한다. 프로모션 달성액은 예상이며 확정은 보험사 정산을 따른다는 문구를 함께 둔다.

- 처음에는 앱 안의 알림함으로 보낸다. 휴대폰 홈 화면에 앱을 추가한 사람에게는 푸시도 보낸다.
- 사람마다 종류별로 끌 수 있다. 같은 날 알림은 묶어서 보낸다.
- 알림 문구에는 고객 이름과 연락처를 넣지 않는다.
- 시점의 날짜 수는 기본값이고 조직별 설정에서 바꾼다.

## 9. 개인정보, 보안, 운영

- **최소 수집**: 주민등록번호와 계좌번호는 저장하지 않는다. 적재 파일에 들어 있으면 적재 단계에서 버린다.
- **가림**: 목록에서는 연락처 가운데 자리를 가리고 상세 화면에서만 전체를 보여 준다.
- **접속**: 사번과 비밀번호로 시작한다. 초기 비밀번호는 첫 접속 때 바꾸게 하고, 여러 번 틀리면 잠근다. 해촉하면 계정을 바로 중지한다.
- **내려받기**: 권한 범위 안에서만 되고 기록을 남긴다.
- **저장**: 전송 구간을 암호화하고 비밀번호는 되돌릴 수 없게 저장한다. 매일 백업하고 되살리기를 시험한다.
- **동의와 보관**: 고객 정보의 수집 동의 확인과 해촉 설계사의 고객 정보 처리는 준법 담당의 확인이 필요하다. 12장에 올린다.
- **장애 대비**: 앱이 멈춰도 업무가 서지 않게 권한 범위의 자료를 엑셀로 내보낼 수 있게 한다.

## 10. 기술 구성

| 층 | 지금 | 목표 | 이유 |
| --- | --- | --- | --- |
| 서버 | 없음 | Python 웹 서버 | 계산 엔진과 적재기를 그대로 쓴다 |
| 자료 저장 | SQLite 파일 | PostgreSQL | 여러 사람이 동시에 쓰고 백업하기 쉽다. 지금 스키마와 호환된다 |
| 화면 | Streamlit, 한 사람용 | 반응형 웹. 휴대폰 홈 화면에 추가 | 앱 장터 없이 배포하고 혼자 운영할 수 있다 |
| 인증 | 없음 | 로그인과 서버 쪽 범위 검사 | 역할과 조직 범위를 강제한다 |
| 긴 작업 | 화면에서 바로 실행 | 뒤에서 실행하고 끝나면 알림 | 큰 파일 적재가 화면을 멈추지 않는다 |
| 배포 | 내 PC | 클라우드 한 곳, 자동 백업 | 설계사가 휴대폰으로 접속한다 |

- 1단계에서는 지금 화면을 메인 관리자의 운영 도구로 계속 쓴다. 2단계에서 새 화면으로 옮긴다.
- 계산과 권한은 자동 시험으로, 화면은 브라우저 자동 점검으로 확인한다.
- 서버 위치와 비용은 2단계 시작 전에 선택지를 정리해 묻는다.

## 11. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 시상안의 금액이 그림에만 있다 | 구간 직접 입력 화면과 원문 보기를 둔다 |
| 원본 양식이 바뀐다 | 매핑에 버전을 두고 적재 전에 머리글을 검사한다. 실패하면 사유를 보여 준다 |
| 실적이 실시간이 아니다 | 기준 시각을 표시하고 적재 주기를 정해 알린다 |
| 예상액과 실제 지급이 다르다 | 예상으로 표기하고 확정은 정산서를 따른다고 적는다 |
| 설계사가 접속하지 않는다 | 알림과 홈 카드로 들어올 이유를 만들고 첫 달에 접속률을 잰다 |
| 개인정보가 샌다 | 9장의 원칙과 접근 기록 |
| 운영이 한 사람에게 달려 있다 | 대리 지정, 운영 안내서, 자료 자동 가져오기 |
| 계약 엑셀의 계약자 이름이 가려져 있다 | DB와 이을 키를 따로 정한다 |
| 조직이 자주 바뀐다 | 이동 이력으로 관리하고 실적은 계약 시점 소속에 둔다 |
