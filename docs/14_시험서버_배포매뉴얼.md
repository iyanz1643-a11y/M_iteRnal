# 시험 서버에 올려 구동 확인하기

이 앱을 서버 한 대에 올려 휴대폰과 PC에서 눌러 보는 순서다. 시험용이다. 운영 배포(D-14)가 아니다. 서버 위치와 비용을 정하는 일은 D-14에 남아 있고, 이 글은 그 전에 구동을 확인하는 용도다.

이 글의 명령은 서버에서 한 줄씩 붙여 넣어 실행한다. `<...>` 로 적은 곳은 자기 값으로 바꾼다. 비밀번호, 키, 접속 정보는 채팅이나 문서에 적지 않는다.

## 1. 큰 순서

| 절 | 하는 일 | 걸리는 시간 |
| --- | --- | --- |
| 3 | 서버를 만들고 접속 범위를 막는다 | 20분 |
| 4 | 서버에 도커를 설치하고 코드를 받는다 | 15분 |
| 5 | 설정 파일을 채운다 | 10분 |
| 6 | 샘플 자료로 구동을 확인한다 | 10분 |
| 7 | 주소와 HTTPS를 붙인다 | 20분 |
| 8 | 실제 자료로 바꿔 확인한다. 실제 자료가 서버에 올라가는 단계다 | 30분 |
| 12 | 쓰고 난 뒤 정리한다 | 10분 |

6절의 샘플 확인이 끝나기 전에는 8절로 가지 않는다. 샘플에서 안 되는 것은 실제 자료에서도 안 된다.

## 2. 준비물

| 준비물 | 내용 |
| --- | --- |
| 서버 | 우분투 22.04 또는 24.04. 2코어, 메모리 4GB, 디스크 40GB 이상이면 시험에 충분하다 |
| 도메인 | 실제 자료를 올릴 때는 필수다. 주소가 없으면 HTTPS를 붙일 수 없다 |
| 저장소 접근 | 이 저장소는 비공개다. 읽기 전용 접근 키(GitHub 배포 키 또는 읽기 전용 토큰)를 만든다 |
| 실제 자료 | 사원현황 폴더, 계약현황 파일, 본부장 지정 파일. 8절에서 서버로 옮긴다 |
| 대표님 접속 주소 | 방화벽에서 허용할 대표님의 접속 IP |

서버는 국내 클라우드나 개인용 VPS 어느 쪽이든 된다. 사양만 맞으면 업체는 상관없다.

## 3. 서버 만들고 막기

1. 서버를 만든다. 접속은 SSH 키로만 한다. 비밀번호 접속은 끈다.
2. 방화벽(보안 그룹)을 이렇게 둔다.

| 포트 | 허용 대상 | 뜻 |
| --- | --- | --- |
| 22 | 대표님 접속 IP만 | 서버 관리 |
| 80, 443 | 대표님 접속 IP만. 시험 기간 동안은 모두 열지 않는다 | 앱 접속과 HTTPS 발급 |
| 8000 | 열지 않는다 | 앱 본체. 프록시가 안에서만 부른다 |

HTTPS 인증서를 받는 첫 순간에는 80번 포트가 열려 있어야 할 수 있다. 막혀서 인증서가 안 받아지면 그 순간만 80번을 열고, 받은 뒤 다시 막는다.

3. 디스크 암호화 옵션이 있으면 켠다. 실제 계약 자료가 올라가기 때문이다.

## 4. 도커 설치와 코드 받기

서버에 접속해서 실행한다.

```
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER      # 적용하려면 접속을 끊었다 다시 연다
docker compose version             # 버전이 나오면 된다
```

코드를 받는다. 작업 브랜치 이름은 `ccr-884af5cc-5ial7r` 다. 병합된 뒤에는 `main` 을 받는다.

```
mkdir -p ~/ga && cd ~/ga
git clone --branch ccr-884af5cc-5ial7r https://github.com/iyanz1643-a11y/m_iternal.git app
cd app
```

비공개 저장소라 비밀번호를 물으면 읽기 전용 토큰을 넣는다. 토큰은 서버의 `~/.git-credentials` 같은 곳에 남기지 말고 받은 뒤 지운다.

## 5. 설정 파일 채우기

```
cp .env.example .env
nano .env
```

`.env` 에서 아래만 채운다. 나머지는 비워 두면 기본값이다. `.env` 는 저장소에 올리지 않는다.

| 이름 | 넣을 값 |
| --- | --- |
| `APP_SECRET` | `openssl rand -hex 32` 로 만든 긴 문자열. 비우면 켤 때마다 모두 로그아웃된다 |
| `APP_HTTPS` | 7절 전까지는 비운다. HTTPS를 붙인 뒤 `1` 로 바꾼다 |
| `APP_BASE_URL` | HTTPS를 붙인 뒤 `https://<도메인>` |
| `FORWARDED_ALLOW_IPS` | `*`. 8000번 포트를 방화벽으로 막았을 때만 쓴다 |
| `DEMO_PASSWORD` | 샘플 계정 비밀번호. 기본값 `demo1234` 를 그대로 두지 않는다 |
| `POSTGRES_PASSWORD` | 아무 긴 문자열. 지금 앱은 쓰지 않지만 구성 파일이 이 값을 요구한다 |
| `BACKUP_KEY` | 백업 암호화 키. 로그인 비밀번호와 다르게 정하고 따로 보관한다 |

`APP_HTTPS` 를 비워 둔 채 HTTP로 접속하는 것은 샘플 자료를 볼 때만 한다. 실제 자료는 HTTPS를 붙인 뒤에만 연다.

## 6. 샘플 자료로 구동 확인

```
docker compose --profile demo run --rm demo     # 샘플 자료와 샘플 계정을 만든다
docker compose up -d --build app worker         # 앱과 워커를 띄운다
docker compose ps                               # app 이 healthy 로 보이면 된다
curl -s localhost:8000/healthz                  # status 가 ok 로 나온다
```

`db` 서비스는 띄우지 않는다. 지금 앱은 SQLite 파일 하나를 쓴다.

HTTPS 전에는 서버 안에서만 열린다. PC에서 임시로 보려면 SSH 터널을 쓴다.

```
ssh -L 8000:127.0.0.1:8000 <서버 사용자>@<서버 주소>
```

이 상태에서 PC 브라우저로 `http://localhost:8000` 을 열면 된다. 아이디는 `admin`, 비밀번호는 `.env` 의 `DEMO_PASSWORD` 다. 쿠키가 안 붙으면 `APP_HTTPS` 가 비어 있는지 본다.

샘플로 확인할 것은 9절 체크리스트의 1에서 4번과 7번이다.

## 7. 주소와 HTTPS 붙이기

이 절을 마친 뒤에 8절로 간다. 도메인의 A 레코드를 서버 IP로 맞춘다. 그다음 서버에 캐디를 설치한다. 인증서는 캐디가 자동으로 받는다.

```
sudo apt-get install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt-get update && sudo apt-get install -y caddy
```

`/etc/caddy/Caddyfile` 를 이렇게 바꾼다.

```
<도메인> {
    reverse_proxy 127.0.0.1:8000
}
```

```
sudo systemctl reload caddy
```

`.env` 에서 `APP_HTTPS=1`, `APP_BASE_URL=https://<도메인>` 으로 바꾸고 앱을 다시 띄운다.

```
docker compose up -d app worker
```

앱은 도커가 `0.0.0.0:8000` 으로 열기 때문에 방화벽이 8000번을 막고 있어야 한다. 3절의 표를 다시 확인한다.

## 8. 실제 자료로 바꿔 확인

실제 자료는 이름과 계약 금액이 들어 있다. 아래를 지킨다.

| 지킬 것 | 이유 |
| --- | --- |
| 6절 샘플 확인이 끝나고 7절 HTTPS가 붙고 방화벽이 닫힌 뒤에만 한다 | 실제 자료가 인터넷에 열리지 않게 한다 |
| 실제 자료는 저장소에 올리지 않는다 | `data/` 는 저장소에서 빠져 있다 |
| 시험이 끝나면 서버의 실제 자료와 DB를 지운다 | 12절 |

### 8.1 서버로 옮기기

PC에서 서버로 올린다. 폴더 이름은 아래처럼 맞춘다.

```
~/ga/real/
    사원현황/                      인별업적순위, 보험사별 파일, 계약현황 파일
    org_heads_local.yaml           본부장 지정 파일. 이름은 이 파일에만 둔다
```

```
scp -r <PC의 사원현황 폴더> <서버 사용자>@<서버 주소>:~/ga/real/
scp <PC의 org_heads_local.yaml> <서버 사용자>@<서버 주소>:~/ga/real/
```

서버에서 도커 안의 사용자가 이 폴더에 쓸 수 있게 한다.

```
sudo chown -R 10001:10001 ~/ga/real
```

### 8.2 DB 만들기

앱을 잠시 멈추고 실제 자료로 DB를 만든다. 비밀번호는 입력창으로 받아 화면과 기록에 남기지 않는다.

```
cd ~/ga/app
docker compose stop app worker
read -s -p "대조용 계정 비밀번호: " TRIAL_PASSWORD; export TRIAL_PASSWORD; echo
docker compose run --rm --no-deps -e TRIAL_PASSWORD -v ~/ga/real:/app/data/real app \
  python scripts/build_trial_db.py --out /app/data/real/trial.db \
    --src /app/data/real/사원현황 --months /app/data/real/trial_months.yaml \
    --heads /app/data/real/org_heads_local.yaml \
    --contracts "/app/data/real/사원현황/<계약현황 파일 이름>.xlsx"
```

끝에 건수만 나온다. 계약현황 줄에서 넣은 계약 수와 "대조 맞음" 이 보이면 된다. 이름이나 금액은 나오지 않는다. "막힌 행" 이 0이 아니면 멈추고 알려 주어야 한다.

만든 DB를 앱의 DB 자리로 옮기고 다시 띄운다. 샘플 DB는 이 명령으로 덮어쓴다.

```
docker compose run --rm --no-deps -v ~/ga/real:/app/data/real app cp /app/data/real/trial.db /app/data/app.db
docker compose up -d app worker
unset TRIAL_PASSWORD
```

로그인은 `admin` 이고 비밀번호는 방금 입력한 값이다. 본부장 번호 `T0001` 꼴 아이디도 같은 비밀번호다.

## 9. 구동 체크리스트

| 번호 | 확인 | 기준 |
| --- | --- | --- |
| 1 | `https://<도메인>/healthz` | status 가 ok |
| 2 | 로그인 | `admin` 으로 들어간다. 틀린 비밀번호를 다섯 번 넣으면 10분 잠긴다 |
| 3 | 프로모션, 달성 현황 | 조직별 보기가 열린다 |
| 4 | 휴대폰으로 같은 주소 | 아래 탭이 보이고 표가 가로로 넘치지 않는다 |
| 5 | 흥국화재 BOOM-UP 조직별 표 | 이터널 합계가 10월 대상 123명 달성 31명, 11월 대상 31명 달성 14명, 합산 40만 달성 10명 |
| 6 | DB생명 여행시상 조직별 표 | 이터널 합계가 10월 달성 4명, 11월 연속 달성 1명, 합산 100만 달성 0명 |
| 7 | 숫자를 누른다 | 명단이 열리고 사람을 누르면 계약별 금액이 나온다 |
| 8 | 로그아웃 후 주소 직접 입력 | 로그인 화면으로 돌아간다 |

5와 6번은 2026년 11월 18일 계약현황으로 만든 숫자다. 다른 파일을 올리면 달라진다. 샘플 자료로 볼 때는 5와 6번을 건너뛰고 7번만 본다.

## 10. 운영 명령

| 하는 일 | 명령 |
| --- | --- |
| 상태 | `docker compose ps` |
| 기록 보기 | `docker compose logs -f --tail 200 app` |
| 다시 시작 | `docker compose restart app worker` |
| 코드 갱신 | `git pull && docker compose up -d --build app worker` |
| 백업 | `docker compose run --rm --no-deps app python scripts/backup_db.py --out /app/data/backup` |
| 멈춤 | `docker compose stop app worker` |

백업은 `.env` 의 `BACKUP_KEY` 로 암호화된다. 키를 잃으면 되살릴 수 없다. 서버가 다시 켜져도 도커가 앱을 자동으로 올린다(`restart: unless-stopped`).

## 11. 문제가 생기면

| 증상 | 확인할 것 |
| --- | --- |
| 로그인 화면에서 계속 돌아온다 | `.env` 의 `APP_HTTPS` 가 1인데 HTTP로 접속했거나, 반대로 HTTPS인데 비어 있다. 바꾸고 앱을 다시 띄운다 |
| 502나 접속 거부 | `docker compose ps` 로 app 상태를 본다. `docker compose logs app` 의 끝줄을 본다 |
| 접속이 안 된다 | 방화벽 허용 IP가 대표님 현재 접속 IP와 같은지 본다. 접속 IP가 바뀌었을 수 있다 |
| HTTPS 인증서가 안 받아진다 | 도메인 A 레코드와 80번 포트를 본다. 위 3절의 안내를 따른다 |
| 로그인 횟수 제한에 걸린다 | 10분 뒤 다시 한다. 자주 걸리면 `FORWARDED_ALLOW_IPS` 를 본다 |
| 디스크가 찬다 | `docker system df`. `docker image prune` 으로 안 쓰는 이미지를 지운다 |
| `healthz` 가 503 | DB 파일이 없거나 깨졌다. 8.2절을 다시 한다 |

## 12. 끝낸 뒤 정리

시험이 끝나면 실제 자료를 서버에 남기지 않는다.

```
cd ~/ga/app
docker compose down -v          # 앱, 워커, DB 볼륨을 지운다
sudo rm -rf ~/ga/real           # 올린 실제 자료와 만든 DB
```

이어서 서버를 지우거나 스냅숏을 지우고, 방화벽 규칙을 정리한다. 백업 파일은 대표님이 정한 곳에만 둔다.
