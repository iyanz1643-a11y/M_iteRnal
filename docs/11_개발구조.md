2026년 11월 14일 기준이다. 무엇을 만드는지는 `09_기능기획서.md`, 어떤 순서로 만드는지는 `10_개발계획.md` 에 있다. 이 문서는 무엇으로, 어떤 구조로 만드는지를 정한다.

## 2. 시스템 구조

```
브라우저 (PC, 휴대폰)
    |
웹 화면        app/web                로그인, 메뉴, 권한과 조직 범위 검사
    |
업무 로직      app/engine, app/loader 계산, 적재, 해석. 화면을 모른다
    |
자료 저장      schema/schema.sql      원본, 원장, 계산 결과, 조회용 뷰
```

지키는 규칙은 다섯 가지다.

1. 화면은 업무 로직을 부르고, 업무 로직은 화면을 모른다. 계산은 화면 없이도 시험할 수 있다.
2. 권한은 화면이 아니라 서버 한 곳에서 막는다. 메뉴를 숨기는 것은 편의일 뿐이다.
3. 메뉴와 권한의 원본은 `config/menu.yaml` 하나다. 화면의 메뉴, 권한 검사, 이 문서의 메뉴 표가 모두 그 파일에서 나온다.
4. 원본 자료는 지우지 않는다. 계산 결과는 언제든 다시 만들 수 있게 둔다.
5. 환경마다 다른 값과 비밀 값은 코드에 넣지 않고 환경 변수로 준다.

## 3. 저장소 구조

```
app/
  web/            웹 화면
    main.py       진입점. 앱, 세션, CSRF, 라우터 등록
    deps.py       권한 검사 guard, CSRF 토큰, DB 연결, 화면 그리기
    routes/       메뉴 묶음별 주소. auth, home, me, org, promo, staff, team
    auth.py       계정, 역할, 범위, 로그인 잠금
    menu.py, templates/, static/
  org/            조직 계층 설정 읽기, 조직장과 대리, 사원현황과 계약현황에서 조직 동기화
  connect/        운영 연결 어댑터. 원본과 해시 보관, 중복 막기, 재시도, 처리기 등록부, 명함 사이트 읽기
  engine/         계산: 수수료, 업적, 시상, 랭킹, 대사, 커리어패스, 인증
    classify.py   계약의 구분과 업권을 읽는 한 곳
    orgs.py       조직과 그 아래 전부의 범위
  loader/         적재: 엑셀 적재기, 실제 계약현황 56열, 사원현황 파서, 시상 공문 PDF, 시상안 원장
  ui.py           기존 운영 도구 (Streamlit)
  db.py, masters.py, samples.py, periods.py
config/
  menu.yaml       메뉴 구성의 원본
  org_levels.yaml 조직 여섯 단계와 파일 열의 짝
  mapping/        원본 파일별 열 매핑, 상품종류 분류표
schema/schema.sql 테이블과 뷰
tests/            자동 시험
docs/             설계와 기획 문서 01~13
scripts/          컨텍스트 점검
.github/workflows CI
samples/          샘플 엑셀과 PDF
templates/        마스터 입력 양식
data/             DB 파일과 올린 원본. 저장소에 올리지 않는다
run_demo.py       샘플 자료로 전체를 한 번 돌린다
```

화면 주소는 `app/web/routes/` 에 메뉴 묶음별 파일로 나눠 둔다. 새 주소는 모두 `app/web/deps.py` 의 guard 를 단다.

## 4. 메뉴 구성

### 4.1 원칙

- 메뉴는 하나이고, 역할에 따라 보이는 항목과 범위가 달라진다.
- 주소의 첫 마디가 묶음이다. `/promo/list` 는 프로모션 묶음의 진행 중 프로모션이다.
- PC 는 왼쪽에 묶음별 메뉴를 둔다. 휴대폰은 아래에 홈, 내 진척, 프로모션, 영업·제안 네 탭을 두고 나머지는 더보기에 모은다.
- 아직 만들지 않은 화면도 메뉴에 있고, 들어가면 무엇이 들어오는지와 어느 단계인지를 보여 준다.
- 관리자가 하는 일은 팀 관리 묶음에, 알림함과 일정과 공지는 공통 묶음에 모았다. 그래서 `10_개발계획.md` 의 열한 묶음이 열세 묶음이 됐다.

## 5. 권한 구조

- **역할은 계정에 적지 않는다.** 메인 관리자 표시가 있으면 메인 관리자, 지금 조직장으로 지정돼 있으면 관리자, 아니면 설계사다. 조직장 지정이 끝나면 따로 손대지 않아도 설계사로 돌아간다.
- **조직 범위**는 조직장으로 지정된 조직과 그 아래 전부다. 본인 것은 언제나 본다.
- **검사 위치**는 `app/web/deps.py` 의 `guard` 하나다. 요청한 주소를 메뉴에서 찾아, 그 역할에게 열려 있지 않으면 403 으로 막고 기록한다.
- **자료 조회**는 범위 안의 설계사 목록을 받아서만 한다. 화면이 사번을 넘겨도 범위 밖이면 나오지 않는다.
- **계정 보호**는 비밀번호를 다섯 번 틀리면 10분 잠그고, 중지하면 열려 있던 접속도 끊는다.
- **CSRF**는 POST 폼마다 `app/web/deps.py` 의 토큰을 확인한다.
- **기록**은 로그인, 로그인 실패, 권한 밖 접근, 계정 처리, 비밀번호 변경을 남긴다.

## 6. 환경

| 환경 | 자료 | 쓰임 |
| --- | --- | --- |
| 개발 | 샘플 자료, SQLite | 만들고 화면을 확인한다 |
| 시험 | 시험마다 새로 만든 빈 DB | 자동 시험 |
| 운영 | 실제 자료, PostgreSQL | 2단계 전에 만든다 |

| 환경 변수 | 뜻 |
| --- | --- |
| `APP_DB` | DB 파일 위치. 없으면 `data/demo.db` |
| `APP_SECRET` | 세션 서명 키. 없으면 켤 때마다 새로 만들어 접속이 끊긴다 |
| `APP_HTTPS` | 1 이면 쿠키를 암호화 연결에서만 보낸다. 운영에서는 1 |
| `CONNECT_STATE_DB` | 연결 상태 표와 명함 연결 표를 쓰는 DB. 없으면 `data/demo.db`. 상세는 `13_AI운영설계.md` 3.5 |
| `DEMO_PASSWORD` | 샘플 계정의 비밀번호. 없으면 demo1234. 운영에서는 샘플 계정을 만들지 않는다 |

실행은 이렇게 한다.

```
python run_demo.py                          # 샘플 자료와 샘플 계정 생성
uvicorn app.web.main:app --port 8000        # 새 웹 화면. admin 또는 사번으로 로그인
streamlit run app/ui.py                     # 기존 운영 도구
python -m pytest tests                      # 자동 시험
```
