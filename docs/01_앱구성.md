# 01. 앱 구성 (아키텍처)

## 1. 목적과 범위

| 영역 | 해결할 문제 |
|------|-------------|
| 수수료 관리 | 보험사별·상품별·회차별 수수료율이 다르고, 정산서 형식이 제각각이라 내부 계산과 맞춰 보기 어렵다 |
| 구간시상 관리 | 월/분기 실적 구간에 따른 시상 금액을 수기로 계산하면 자격 조건(유지율, 건수, 환수)을 놓친다 |
| 업적 관리 | 설계사별 신계약·환산보험료·유지율을 조직 이동 이력까지 반영해 집계해야 한다 |
| 점검(대사) | 보험사가 지급한 금액과 내부에서 계산한 금액의 차이를 계약 단위로 찾아내고 처리 이력을 남겨야 한다 |

범위에서 제외: 청약 설계(가입설계 시스템), 고객 CRM, 급여 이체 처리. 이 앱은 **정산 확정 금액**을 산출하는 데서 끝난다.

## 2. 월 마감 업무 흐름

```
D+1~5   보험사 정산서·계약현황·유지현황 수신 (포털 다운로드 / 이메일)
  │
  ▼
[1] 수집   원본 파일 보관 + 적재 배치 등록 (파일명, 해시, 기간, 건수)
  │
  ▼
[2] 정규화 보험사별 컬럼 매핑 → 표준 스키마 적재, 키 정규화, 품질검증
  │
  ▼
[3] 업적   계약 상태 반영, 환산보험료 산출, 설계사·조직 기준 집계, 유지율 갱신
  │
  ▼
[4] 수수료 수수료율 규칙 적용 → 초회/계속/유지/시책/환수 내부 계산
  │
  ▼
[5] 시상   구간시상 규칙 적용 → 자격 판정, 구간 결정, 시상액 산출, 시상 환수
  │
  ▼
[6] 점검   보험사 정산서 vs 내부 계산 대사 → 차이 목록 생성 → 담당자 처리
  │
  ▼
[7] 확정   월 마감 잠금, 설계사별 수수료 명세 생성·배포, 스냅샷 보관
```

마감 후 발견된 오류는 해당 월을 다시 열지 않고 **다음 월에 보정 레코드**로 반영한다.

## 3. 모듈 구성

### 3.1 데이터 수집 (Import)
- 파일 업로드 화면: 보험사, 데이터 유형(정산서/계약현황/유지현황/환수내역), 대상 월 선택
- 원본 파일을 변경 없이 저장소에 보관하고 `import_batch`에 메타데이터 기록
- 동일 파일(해시 일치) 재업로드 차단, 동일 기간 재업로드는 새 버전으로 기록

### 3.2 마스터 관리
- 보험사, 상품(환산율 포함), 설계사, 조직, 설계사의 보험사별 코드 매핑
- 수수료율 규칙: 보험사 × 상품(또는 상품군) × 수수료 유형 × 회차 구간 × 적용 기간
- 구간시상 규칙: 기간 유형, 측정 지표, 구간 테이블, 자격 조건, 환수 조건
- 모든 마스터는 **적용 시작일/종료일**을 가져 과거 월 재계산이 가능하다

### 3.3 업적 관리
- 계약 원장: 증권번호 기준 단일 레코드, 상태 변경은 이력 테이블에 누적
- 환산보험료 계산: 월납보험료 × 상품 환산율 (납입 방식별 월납 환산 포함)
- 집계 기준일 정책: 보험사마다 다른 "성립일/승인일/초회납입일"을 내부 기준으로 통일
- 설계사 실적은 **해당 월 소속 조직 이력** 기준으로 집계
- 유지율(13회차, 25회차) 월별 산출

### 3.4 수수료 계산 엔진
- 입력: 계약, 납입 회차, 수수료율 규칙
- 출력: 계약·회차·수수료유형 단위의 계산 레코드 (근거 규칙 ID 포함)
- 환수: 해지·실효·철회 시 미경과 수수료 환수액 산출 (보험사별 환수 비율표 적용)
- 재계산은 항상 **계산 실행(run) 단위**로 묶여 이전 결과와 비교 가능

### 3.5 구간시상 엔진
- 측정 지표: 환산보험료 합계, 건수, 신규 보험사 비중 등 규칙에서 선택
- 구간 테이블: 하한/상한/보상 방식(정률·정액)
- 자격 조건: 유지율 하한, 최소 건수, 위촉 경과 개월, 제외 상품
- 시상 환수: 시상 대상 계약이 N개월 내 해지되면 비례 환수
- 결과 레코드에 "미자격 사유"를 남겨 설계사 문의 대응

### 3.6 점검(대사) 모듈
- 보험사 정산서 라인 ↔ 내부 계산 레코드를 (증권번호, 수수료유형, 회차)로 매칭
- 차이 유형 자동 분류: 율 차이, 누락 계약, 상태 불일치, 환산 차이, 보험사 단독 지급, 내부 단독 계산
- 차이 건별 담당자 배정, 처리 상태, 메모, 처리 완료 시 보정 레코드 연결
- 허용 오차(원 단위 절사 등) 설정

### 3.7 리포트·대시보드
- 설계사별 수수료 명세서 (월)
- 조직별 업적 현황, 구간 분포
- 보험사별 정산 대사 요약 (일치율, 미처리 차이 금액)
- 유지율 추이

### 3.8 권한·감사
- 역할: 관리자 / 정산 담당 / 조직장(소속 조회만) / 설계사(본인 조회만)
- 마스터 변경, 마감, 보정 레코드 생성은 감사 로그 필수

## 4. 계층 아키텍처 (데이터 관점)

```
┌──────────────────────────────────────────────────────────┐
│ Raw      원본 파일 그대로 (xlsx/csv/pdf) + import_batch    │  불변
├──────────────────────────────────────────────────────────┤
│ Staging  원본 행을 1:1로 텍스트 보존 (raw_row)             │  불변
├──────────────────────────────────────────────────────────┤
│ Core     표준 스키마 (contract, commission_statement_line, │  append-only
│          premium_payment, persistency ...) + 마스터        │
├──────────────────────────────────────────────────────────┤
│ Calc     commission_calc, incentive_result (run 단위)      │  run마다 새로 생성
├──────────────────────────────────────────────────────────┤
│ Mart     월별 집계, 명세서, 대시보드용 뷰                   │  재생성 가능
└──────────────────────────────────────────────────────────┘
```

Raw·Staging은 삭제·수정하지 않고, Core는 추가만 하며, Calc·Mart는 언제든 다시 만들 수 있어야 한다.

## 5. 기술 스택 옵션

| 단계 | 구성 | 적합한 상황 |
|------|------|-------------|
| A. 경량 | Google Sheets + Apps Script, 또는 Excel + Power Query | 보험사 3개 이하, 설계사 50명 이하, 담당자 1명 |
| B. 중간 (추천) | Python(pandas) + SQLite/PostgreSQL + Streamlit 또는 FastAPI + 간단한 웹 UI | 보험사 5~15개, 설계사 수백 명, 월 수천~수만 라인 |
| C. 본격 | Next.js/React + PostgreSQL(Supabase) + 배치 워커 + 파일 스토리지 | 다수 지사, 역할별 권한, 설계사 셀프 조회 필요 |

**추천은 B**다. 이유는 다음과 같다.
- 수수료·시상 로직은 표 형태 규칙 처리라 pandas가 가장 빠르게 검증된다.
- 스키마가 `schema/schema.sql`로 고정되어 있어 나중에 C로 옮겨도 데이터 구조는 그대로 간다.
- 보험사별 매핑을 YAML로 관리하면 비개발자도 새 보험사 형식을 추가할 수 있다.

A는 마스터의 적용 기간 관리와 감사 로그가 어려워 6개월 이상 운영하면 한계가 온다.

## 6. 화면(메뉴) 구성

```
대시보드
├─ 이달 마감 현황 (수신/적재/계산/대사/확정 단계)
├─ 미처리 대사 차이 건수·금액
└─ 조직별 업적 요약

데이터 수집
├─ 파일 업로드 (보험사)
├─ 본부 계약 업로드 (본부별 권한)
├─ 시상 공문 PDF 등록 / 추출 결과 검토
├─ 외부 지표 업로드 (불완전판매·민원·교육)
├─ 적재 배치 이력
└─ 품질검증 결과

마스터
├─ 보험사 / 상품(환산율)
├─ 설계사 / 조직 / 보험사 코드 매핑
├─ 수수료율 규칙
└─ 구간시상 규칙

업적
├─ 계약 원장 (검색, 상태 이력)
├─ 청약 현황 (예정 업적, 철회 가능 건)
├─ 설계사별 실적 (월 / 분기 / 반기 / 연)
├─ 조직별 실적 (월 / 분기 / 반기 / 연)
├─ 본부 업로드 ↔ 보험사 현황 대조
└─ 유지율

수수료
├─ 계산 실행 / 실행 이력
├─ 설계사별 명세
└─ 환수 내역

구간시상
├─ 월별 규칙 (PDF 원본 연결, 버전)
├─ 계산 실행
├─ 결과 (자격/구간/금액/미자격 사유)
└─ 시상 환수

커리어패스
├─ 직급 체계 / 승격 기준
├─ 개인 목표 설정·진척
└─ 승격 후보

인증 관리
├─ 프로그램 / 연도별 기준
├─ 설계사별 진척 (MDRT, 우수인증설계사)
└─ 수상 기록

점검(대사)
├─ 보험사별 대사 요약
├─ 차이 목록 (유형·담당자·상태 필터)
└─ 보정 레코드

마감
├─ 월 마감 / 잠금
└─ 명세서 배포

설정
├─ 사용자 / 역할
└─ 감사 로그
```

## 7. 구축 로드맵

| 단계 | 기간(안) | 산출물 |
|------|----------|--------|
| 1. 데이터 기반 | 2~3주 | 스키마 생성, 보험사 2곳 매핑, 원본 보관·적재·품질검증 |
| 2. 업적 | 2주 | 계약 원장, 환산보험료, 조직 이력 집계, 유지율 |
| 3. 수수료 | 2~3주 | 수수료율 규칙 입력, 계산 엔진, 환수, 설계사 명세 |
| 4. 대사 | 2주 | 정산서 매칭, 차이 분류, 처리 워크플로 |
| 5. 구간시상 | 2주 | 규칙 입력, 자격 판정, 시상 계산, 시상 환수 |
| 6. 마감·권한 | 1~2주 | 월 마감 잠금, 보정 레코드, 역할별 권한, 감사 로그 |
| 7. 나머지 보험사 확장 | 보험사당 2~3일 | 매핑 파일 추가, 검증 |
| 8. 커리어·인증 | 2~3주 | 직급·승격 기준·목표, 인증 프로그램·연도 기준·진척·수상 (`docs/05_확장기능.md`) |

1~4단계를 먼저 끝내 **"보험사가 준 돈이 맞는지"** 부터 확인할 수 있게 하고, 구간시상은 그 위에 얹는다.
