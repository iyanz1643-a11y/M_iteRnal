# 03. 로우데이터 관리법

보험사에서 내려오는 파일은 형식이 제각각이고, 같은 보험사도 분기마다 컬럼이 바뀐다.
그래서 **원본 보관 → 매핑 → 표준 적재 → 검증 → 마감** 다섯 단계를 고정 절차로 만든다.

## 1. 로우데이터 종류

| 구분 | 데이터 | 출처 | 주기 | 핵심 키 |
|------|--------|------|------|---------|
| 보험사 | 수수료 정산서 (지급 명세) | 보험사 GA 포털 다운로드 | 월 | 증권번호, 보험사 설계사코드, 수수료유형, 회차 |
| 보험사 | 신계약 현황 (청약/성립 리스트) | 포털 | 월 또는 주 | 증권번호 |
| 보험사 | 계약 유지 현황 (유지/실효/해지/철회) | 포털 | 월 | 증권번호, 상태, 상태일 |
| 보험사 | 납입 현황 (회차별 입금) | 포털 | 월 | 증권번호, 회차 |
| 보험사 | 환수 내역 | 포털 또는 정산서 내 포함 | 월 | 증권번호, 환수 사유 |
| 보험사 | 설계사 위촉/코드 현황 | 포털 | 변경 시 | 보험사 설계사코드 |
| 내부 | 설계사 명부, 조직도, 소속 변경 | 인사/총무 | 변경 시 | 내부 사번 |
| 내부 | 수수료율표 | 보험사 공문/계약서 | 변경 시 | 보험사, 상품, 회차 |
| 내부 | 구간시상 규칙 | 경영진 결정 | 분기/연 | 규칙명, 적용 기간 |

## 2. 파일 보관 규칙

### 디렉토리 구조
```
raw/
  {보험사코드}/
    {YYYY}/
      {YYYYMM}/
        {YYYYMM}_{보험사코드}_{데이터유형}_v{n}.{ext}
        {YYYYMM}_{보험사코드}_{데이터유형}_v{n}.{ext}.meta.json
```
예: `raw/SAM/2026/202610/202610_SAM_statement_v1.xlsx`

데이터유형 코드: `statement`(정산서), `newbiz`(신계약), `inforce`(유지현황), `payment`(납입), `clawback`(환수), `agentcode`(설계사코드)

### 원칙
1. **원본 파일은 절대 수정하지 않는다.** 열어서 저장도 금지 (Excel은 열기만 해도 서식이 바뀐다). 복사본으로 작업한다.
2. 같은 월·같은 유형을 다시 받으면 `v2`, `v3`로 올린다. 덮어쓰지 않는다.
3. 수신 즉시 `import_batch`에 등록한다: 보험사, 유형, 대상 월, 파일명, SHA-256 해시, 수신 경로(포털/이메일), 수신 일시, 담당자.
4. 해시가 같은 파일은 재적재를 막는다.
5. 이메일로 받은 파일은 메일 원문(.eml)도 같은 폴더에 보관한다.
6. PDF로만 오는 정산서는 PDF 원본 + 표 추출 결과(csv)를 함께 보관하고, 추출 결과는 `v1_extracted`로 표시한다.

## 3. 컬럼 매핑 (보험사별 → 표준)

보험사마다 `config/mapping/{보험사코드}_{데이터유형}.yaml` 한 파일을 둔다. 실제 동작하는 예시는 `config/mapping/SAM_statement.yaml`, `internal_org_contract.yaml` 이다.

매핑 파일이 정의하는 것:
- 헤더가 몇 번째 행인지, 시트 이름이 무엇인지
- 원본 컬럼명 → 표준 컬럼명
- 값 변환: 날짜 형식, 금액 단위(원/천원), 수수료유형 코드 치환, 상태 코드 치환
- 무시할 행 조건 (소계, 합계 행)
- 필수 컬럼

매핑 파일을 고치면 **버전과 적용 시작 월**을 올린다. 같은 보험사가 2026년 7월부터 컬럼을 바꿨다면 `effective_from: 202607`인 새 매핑을 추가하고 이전 매핑은 남겨 둔다. 과거 월 재적재가 가능해야 한다.

### 표준 컬럼 사전 (정산서 기준)
| 표준 컬럼 | 타입 | 설명 |
|-----------|------|------|
| period_ym | TEXT(6) | 정산 월 |
| policy_no | TEXT | 증권번호 (정규화 후) |
| insurer_agent_code | TEXT | 보험사 설계사 코드 |
| product_code | TEXT | 보험사 상품 코드 |
| commission_type | TEXT | initial / renewal / persistency / promo / clawback |
| installment_no | INTEGER | 회차 |
| basis_amount | NUMERIC | 계산 기준 보험료 |
| rate | NUMERIC | 보험사가 적용한 요율 (있으면) |
| amount | NUMERIC | 지급(또는 환수, 음수) 금액 (원) |
| pay_date | DATE | 지급일 |
| raw_ref | TEXT | 원본 시트/행 번호 |

## 4. 키 정규화

| 키 | 규칙 |
|----|------|
| 증권번호 | 앞뒤 공백 제거, 하이픈·공백·점 제거, 영문 대문자, 전각→반각. 정규화 전 값은 `raw_row`에 남긴다 |
| 보험사 설계사 코드 | 앞자리 0 보존 (문자열로 읽기), 공백 제거. 내부 사번과는 `agent_insurer_code`로만 연결 |
| 상품 코드 | 보험사 코드 그대로 보존, 마스터에 없으면 품질 이슈로 올리고 적재는 진행 |
| 날짜 | ISO `YYYY-MM-DD`. Excel 일련번호·`2026.10.01`·`20261001` 모두 변환 |
| 금액 | 정수 원 단위. 천원 단위 파일은 매핑에서 ×1000. 괄호 표기 `(1,000)`은 음수 |
| 월 | `YYYYMM` 문자열 |

## 5. 품질검증 (적재 직후 자동)

| 검사 | 수준 | 처리 |
|------|------|------|
| 필수 컬럼 누락 | 차단 | 적재 중단, 매핑 수정 후 재실행 |
| 증권번호 공백 | 차단 | 행 단위 오류 목록, 해당 행 제외 적재 여부 담당자 선택 |
| 같은 배치 내 (증권번호, 수수료유형, 회차) 중복 | 경고 | 보험사 분할 지급일 수 있어 합산 허용, 목록 보고 |
| 정산서 합계 ≠ 보험사 표기 총액 | 차단 | 매핑(소계 행 포함 등) 점검 |
| 설계사 코드가 매핑에 없음 | 경고 | 미매핑 설계사 목록 → 마스터 등록 후 재매칭 |
| 상품 코드가 마스터에 없음 | 경고 | 상품 등록 후 환산율 반영 |
| 날짜 파싱 실패 | 차단 | 행 오류 목록 |
| 음수 금액인데 유형이 환수가 아님 | 경고 | 확인 |
| 전월 대비 라인 수 ±50% 이상 변동 | 경고 | 파일 누락/중복 의심 |

결과는 `quality_issue` 테이블에 배치별로 저장하고, 차단 등급이 하나라도 있으면 배치 상태를 `failed`로 둔다.

## 6. 적재 정책 (append-only)

- Core 테이블은 **추가만** 한다. 같은 계약이 다음 달 파일에 다시 나오면 상태 비교 후 변경된 것만 `contract_status_history`에 추가하고 `contract`의 현재 상태를 갱신한다.
- 정산서 라인은 배치 단위로 통째로 들어간다. 재적재(v2)는 이전 배치를 `superseded`로 표시하고 새 배치를 `active`로 둔다. 삭제하지 않는다.
- 수기 수정은 금지한다. 보험사 값이 틀렸으면 **보정 레코드(`adjustment`)** 를 추가하고 사유와 근거 파일(공문, 메일)을 연결한다.

## 7. 월 마감과 스냅샷

1. 마감 조건: 모든 보험사 정산서 적재 완료, 차단 등급 품질 이슈 0건, 대사 차이가 전부 `confirmed/adjusted/ignored`.
2. 마감 시 다음을 스냅샷으로 저장한다:
   - 해당 월 `commission_calc`, `incentive_result`, `reconciliation_diff` 전체 → `snapshots/{YYYYMM}/`에 CSV + 해시
   - 사용된 마스터(수수료율, 환산율, 시상 규칙, 조직 소속) 목록
   - 설계사별 명세서 PDF/Excel
3. 마감 후 `close_period.status = closed`. 이후 해당 월 Core 추가, Calc 재실행은 앱에서 차단된다.
4. 마감 후 오류는 다음 월 `adjustment`로 처리하고, 원 월을 참조(`adjusts_period_ym`)한다.

## 8. 개인정보·보안

- 주민등록번호는 적재하지 않는다. 보험사 파일에 있으면 매핑에서 제외하거나 생년월일(앞 6자리)만 남긴다.
- 계약자·피보험자 이름은 Core에 넣되, 설계사 셀프 조회 화면에서는 마스킹(홍*동)한다.
- 원본 파일 저장소는 정산 담당자·관리자만 접근한다. 접근 기록을 남긴다.
- 보관 기간: 원본과 스냅샷은 **최소 5년** (보험업 관련 장부 보존 기준에 맞추되, 회사 내규가 더 길면 내규 우선).
- 백업: 원본 저장소와 DB는 일 1회 외부(클라우드) 백업, 월 마감 스냅샷은 별도 보관.

## 9. 월간 운영 체크리스트

```
[ ] 보험사별 수신 체크표 작성 (받아야 할 파일 n개 중 m개 수신)
[ ] 원본 파일 raw/ 폴더 규칙대로 저장, import_batch 등록
[ ] 매핑 적용 → 적재 → 품질검증 결과 확인, 차단 0건
[ ] 미매핑 설계사/상품 마스터 등록 후 재매칭
[ ] 계약 상태 변경 반영 확인 (해지·실효 건수 전월 대비 이상 없는지)
[ ] 수수료 계산 실행, 전월 대비 총액 변동 사유 확인
[ ] 대사 실행, 차이 유형별 건수·금액 확인, 담당자 배정
[ ] 구간시상 계산, 미자격 사유 샘플 확인
[ ] 차이 전부 처리 → 마감 → 스냅샷 생성 → 명세서 배포
[ ] 이번 달 발생한 매핑 변경·규칙 변경을 변경 이력에 기록
```
