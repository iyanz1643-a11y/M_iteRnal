# 07. 엑셀 적재기, PDF 추출, 구분별 시상, 조직·관리자, 임원제도·어워드·인증

프로토타입에 실제로 구현되어 샘플 파일로 돌아가는 기능을 설명한다. 샘플 원본은 `samples/` 에 있고, `python run_demo.py` 가 같은 파일을 `data/raw/` 에 만들어 적재기로 읽는다.

## 1. 엑셀 적재기

### 본부 계약현황 → 추출 8항목
본부에서 올리는 엑셀에는 열이 많다. 적재기는 매핑(`config/mapping/internal_org_contract.yaml`)에 적힌 열만 뽑는다.

| 추출 항목 | 원본 열 | 저장 위치 | 비고 |
|-----------|---------|-----------|------|
| 사번 | 사번 | agent.internal_code | 마스터에 없으면 그 행은 제외(차단) |
| 성명 | 성명 | agent.name 과 대조 | 불일치하면 경고 |
| 원수사 | 원수사 | insurer | 생명/손해 업권은 원수사 마스터가 가진다 |
| 상품 | 상품명 | product | 마스터에 없으면 경고, 수수료 계산에서 빠진다 |
| 구분 | 구분 | product_category | 종신/건강/저축/연금/재물/자동차/일반. 상품 마스터와 다르면 경고 |
| 보험료 | 보험료 | contract.premium_monthly | 월납 기준 |
| 인정보험료 | 인정보험료 | contract.converted_premium | 보험료 × 인정률과 다르면 경고 |
| 건수 | 건수 | contract.policy_count | 공동모집 0.5 건 등 소수 허용 |

함께 읽는 열: 청약번호(키), 증권번호, 청약일, 계약일, 상태, 상태변경일, 납입주기.

추출 결과는 뷰 `v_contract_extract` 와 화면 "데이터 수집 → 추출 데이터" 에서 그대로 보고 CSV 로 내려받는다.

### 처리 순서
1. **배치 등록**: 파일 SHA-256 해시로 같은 파일 재적재를 막는다. 정산서 재수신은 새 버전이 되고 이전 배치는 `superseded`.
2. **원본 행 보존**: 모든 행을 `raw_row` 에 원문 그대로 저장한다.
3. **매핑·변환**: 날짜(`2026-10-05`, `2026.10.05`, `20261005`, Excel 날짜), 금액(`150,000`, `(1,000)`, `150,000원`), 요율(`800%`), 상태·구분 코드 치환.
4. **청약·철회 필터**: 청약번호가 키다. 처음 보는 건은 신규, 다시 올라온 건은 상태 변화만 이력에 추가한다.
5. **품질검증**: 결과는 `quality_issue` 에 남고, 차단 등급이 미해결이면 월 마감이 잠긴다.

| 검사 코드 | 등급 | 의미 |
|-----------|------|------|
| missing_column | 차단 | 매핑에 적힌 열이 파일에 없음 |
| bad_value / required_blank | 차단 | 값 변환 실패, 필수 값 없음 |
| unmapped_agent / unmapped_insurer | 차단 | 사번·원수사가 마스터에 없음 (행 제외) |
| total_mismatch | 차단 | 파일의 합계 행과 적재 대상 합계가 다름 |
| name_mismatch / org_mismatch | 경고 | 성명 불일치, 업로드 본부 소속이 아님 |
| unmapped_product / unknown_category / category_mismatch | 경고 | 상품·구분 확인 필요 |
| recognized_mismatch | 경고 | 인정보험료가 인정률과 맞지 않음 |
| duplicate_key | 경고 | 같은 파일 안 청약번호 중복 |

### 원수사 정산서
원수사마다 양식이 달라 매핑 파일을 하나씩 둔다.

| 원수사 | 양식 특징 | 매핑에서 처리 |
|--------|-----------|---------------|
| 샘플생명 | 헤더 4행, 지급률 `800%`, 합계 행 | `parse_percent`, `totals_check` |
| 대한생명 | 금액이 문자열, 환수는 `(1,000)`, 증권번호에 공백, 날짜 `2026.11.10` | `parse_money`, `remove`, `parse_date` |
| 한빛손해·미래화재 | 구분이 한 글자(신/계/환/시), 환수가 양수, 날짜 `20261110` | `map`, `post: negate_if` |

### 유지율 현황
원수사별 13회차·25회차 대상/유지 건수를 적재한다. 전체·생명·손해·조직 유지율은 건수를 합산해 계산하므로 시상 조건, 인증, 조직 화면이 같은 값을 쓴다.

### 납입 회차
샘플에는 원수사 납입 현황 파일이 없어, 계약 상태로 그 달 납입 회차를 추정한다(`app/engine/payments.py`). 실운영에서는 납입 현황 파일 적재로 바꾼다.

## 2. 시상 공문 PDF 추출

`app/loader/pdf_incentive.py` 가 pdfplumber 로 본문 줄과 표를 순서대로 읽어 규칙 초안을 만든다.

| 공문에서 읽는 것 | 인식하는 표기 | 결과 |
|------------------|---------------|------|
| 발신 | `발신: 샘플생명` | 원수사 시책이면 그 원수사 계약만 집계 |
| 기간 | `적용 기간: 2026년 1월 ~ 2026년 12월`, `대상 월: 2026년 10월` | effective_from / to |
| 시상 종류 | `[기본시상] …`, `[추가시상] …` | rule_kind = base / extra |
| 대상 구분 | `대상 구분: 종신, 건강` | incentive_rule_category |
| 지표·기간 | `평가 지표: 인정보험료 (월)`, `건수 (분기)` | metric, period_type |
| 구간표 | `50만원 / 100만원 / 10%`, `3건 / - / 10만원` | incentive_tier (정률·정액) |
| 조건 | `13회차 유지율 85% 이상`, `2건 이상`, `위촉 12개월 이상` | incentive_condition |
| 환수 | `6개월 이내 … 환수` | clawback_months |

- 추출 결과는 **초안(draft)** 이다. 화면 "데이터 수집 → 시상 공문 PDF" 에서 구간·조건·경고를 확인하고 검토자 이름을 넣어 승인해야 계산에 쓰인다. 승인은 감사 로그에 남는다.
- 해석하지 못한 부분은 경고로 표시한다. 샘플 11월 한빛손해 공문은 구분 마스터에 없는 "운전자" 가 있어 경고가 붙는다.
- 실제 공문은 양식이 제각각이다. 지금 추출기는 위 표의 표기를 따르는 문서에 맞춰져 있으므로, 실제 공문을 받으면 그 양식에 맞춰 인식 규칙을 넓혀야 한다. 스캔 PDF 는 OCR 이 따로 필요하다.

## 3. 구분별 시상 · 추가시상

- 구분 마스터: 종신, 건강, 저축, 연금, 재물, 자동차, 일반. 기본값으로 종신·건강만 시상 대상이다.
- 실제 판정은 **규칙마다 가진 대상 구분**을 따른다. 대상이 아닌 구분의 계약은 그 규칙의 지표에 들어가지 않는다.
- 화면 "구간시상" 맨 위 표가 기준 월에 구분별로 기본시상·추가시상이 있는지와 해당 규칙을 보여준다.
- 추가시상은 기본시상과 별개 규칙으로 계산해 설계사별로 기본 + 추가 합계를 낸다.
- 업적 화면 "구분별 집계" 가 설계사 × 구분 인정보험료와 시상 대상(종신+건강) 합계를 보여준다.

## 4. 조직 구성과 관리자

- 조직: 본부(hq) → 지점(branch). 설계사는 지점에 소속되고 소속 이력을 가진다.
- 관리자: 본부장·지점장도 사번을 가진 사람으로 `agent`(job_type = manager) 에 있고, `org_manager` 가 어느 조직을 언제부터 맡는지 기록한다.
- 화면 "조직": 본부·지점별 관리자, 설계사 수, 월 순건수, 인정보험료, 가동률, 13·25회차 유지율과 소속 설계사 명단, 소속 변경 이력.
- 본부 엑셀 업로드 시 업로드 본부 소속이 아닌 사번은 경고로 잡힌다.

## 5. 임원제도 · 영업우수 · 명예의전당 · 인증

모두 `certification_program`(분류·대상·업권·원수사) + `certification_criteria`(연도별 기준) 한 구조로 관리한다.

| 분류 | 샘플 프로그램 | 대상 | 판정 지표 |
|------|---------------|------|-----------|
| MDRT | MDRT 회원 | 설계사 | 연 수수료 **또는** 연 초회보험료 |
| 협회 인증 | 우수인증설계사(생명), (손해) | 설계사 | 근속, 업권별 13·25회차 유지율, 불완전판매 0건 |
| 원수사 인증 | 샘플생명 ACE 클럽, 한빛손해 블루리본 | 설계사 | 해당 원수사 연 인정보험료, 해당 원수사 유지율 |
| 설계사 임원제도 | 명예이사, 명예상무 | 설계사 | 연 인정보험료, 유지율, 근속 |
| 관리자 임원제도 | 이사 지점장, 상무 본부장 | 지점장 / 본부장 | 조직 연 인정보험료, 조직 유지율, 인원, 가동률 |
| 어워드 | 영업우수설계사 | 설계사 | 연 누적 인정보험료 순위, 유지율, 불완전판매 0건 |
| 어워드 | 명예의전당 | 설계사 | 영업우수설계사 누적 수상 횟수 (과거 수상 + 올해 달성) |

- 기준 값은 전부 **샘플**이다. MDRT·협회 기준은 매년 공식 공고 값으로, 임원제도·어워드는 사내 규정 값으로 `certification_criteria` 에 넣는다.
- 같은 기준그룹은 모두 충족(AND), 그룹이 여럿이면 하나만 충족(OR)이다.
- 누적 지표는 경과 월 기준으로 연말 값을 추정해 "연말 달성 예상" 을 함께 낸다.
- 실제 수상·인증 기록은 `agent_certification_award` 에 연도별로 남긴다.

## 6. 랭킹과 전월 공유

- 매월 전체 설계사 순위를 `ranking_snapshot` 에 저장한다: 월 / 연 누적, 인정보험료 / 건수, 전 구분 / 시상 대상 구분.
- 당월은 청약·철회가 움직여 순위가 바뀌므로, 화면 "랭킹 · 명예의전당" 은 **확정된 전월 순위**를 공유 대상으로 보여주고 CSV 로 내려받게 한다. 당월 순위는 "집계 중" 으로만 볼 수 있다.
- 연 누적 순위는 영업우수설계사 판정에 그대로 쓰인다.
