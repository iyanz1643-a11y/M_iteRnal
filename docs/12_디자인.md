# 12. 디자인 기준

2026년 11월 16일에 iOS 앱 형식으로 바꿨다. 대표님 지시이고 결정은 `10_개발계획.md` 7.1 의 D-82 다. 11월 17일에 아래 탭을 묶음에서 항목으로 바꿨다. D-83 이다. 같은 날 조직별 진척 표와 명단의 틀을 5.2 에 더했다. D-103 이다. 11월 13일에 정한 반응형, 인포그래픽, 큰 글씨, 단순하고 직관적인 화면이라는 방향은 그대로다. 구현은 `app/web/static/app.css`, `app/web/templates/base.html`, `app/web/templates/_ui.html` 에 있고, 아래 탭의 원본은 `config/menu.yaml` 의 `mobile_tabs` 다.

## 1. 원칙

1. **화면마다 주인공 숫자 하나.** 들어오자마자 가장 큰 글씨로 한 가지를 말한다. 설계사 홈은 이번 달 인정보험료, 관리자 홈은 가동률이다.
2. **글로 설명하기 전에 그림으로 보여 준다.** 비율은 고리, 순위는 눈금 위의 점, 비교는 막대로 그린다.
3. **색은 상태를 뜻할 때만 쓴다.** 초록은 정상과 가동, 주황은 확인 필요, 빨강은 차단과 마감 임박이다. 꾸미려고 색을 쓰지 않는다.
4. **여백으로 나눈다.** 선과 테두리 대신 흰 카드와 회색 바탕, 넉넉한 간격으로 구획한다.
5. **역할마다 자주 쓰는 곳을 아래 탭에 둔다.** 휴대폰에서는 역할별 탭 네 개와 더보기로 모든 화면에 닿는다. 누르는 곳은 48픽셀 이상이다.
6. **모르는 것은 모른다고 적는다.** 금액이 원문에만 있으면 숫자를 지어내지 않고 원문 확인이라고 쓴다. 실적에는 기준 시각을 붙인다.

### 4.1 화면 틀

| 부분 | 규칙 |
| --- | --- |
| 위 막대 | 높이 52픽셀. 처음에는 투명하다. 큰 제목이 막대 밑으로 지나가면 흐린 바탕과 가운데 작은 제목이 나타난다 |
| 뒤로 단추 | 탭 화면에서는 보이지 않는다. 탭에 있는 항목의 묶음이면 그 묶음의 첫 탭으로 간다. 아니면 더보기의 그 묶음 구획을 연다. 이름은 가는 곳의 탭 이름이나 묶음 이름이다 |
| 알약 줄 | 1000픽셀 이하에서 묶음 안 화면을 옆으로 넘기는 알약으로 고른다. 지금 화면이 보이게 넘겨 둔다 |
| 아래 탭 | 1000픽셀 이하. 역할별 네 칸과 더보기. 칸 하나가 화면 하나다. 아이콘은 그 항목의 것이 있으면 쓰고 없으면 묶음의 것을 쓴다 |
| 더보기 | iOS 설정 앱 모양의 전체 화면. 내 정보, 공통 묶음, 홈을 뺀 묶음별 구획, 나가기 순서다. 탭에 있는 항목만 빼고 묶음은 남긴다. 남은 항목이 없는 구획은 그리지 않는다. 아래 탭은 그대로 남는다 |
| 사이드바 | 1001픽셀 이상. iPadOS 형식으로 왼쪽 288픽셀에 앱 이름, 내 정보, 홈과 공통, 묶음별 항목, 나가기를 둔다. 지금 화면을 강조색으로 칠한다 |

역할별 아래 탭은 아래와 같다. 탭 이름이 화면 이름과 다를 수 있다. 그 역할에게 보이지 않거나 모듈이 꺼진 항목은 건너뛴다. 경로와 권한은 탭과 상관없이 같다.

| 역할 | 아래 탭 | 탭이 여는 화면 |
| --- | --- | --- |
| 설계사 | 홈, 프로모션, 달성 현황, 알림, 더보기 | 홈, 진행 중 프로모션, 달성 현황, 알림함 |
| 관리자 | 홈, 프로모션, 팀 달성, 부문 시상, 더보기 | 홈, 진행 중 프로모션, 달성 현황, 조직 부문 시상 |
| 메인 관리자 | 홈, 프로모션, 시상안, 확정, 더보기 | 홈, 진행 중 프로모션, 시상안, 지난 프로모션 |

어느 칸이 켜지는지는 아래 규칙을 따른다. 판정은 `app/web/menu.py` 의 `tab_of` 한 곳이다.

| 지금 화면 | 켜지는 칸 | 뒤로 단추 |
| --- | --- | --- |
| 탭에 있는 화면 | 그 탭 | 없음 |
| 탭에 있는 항목과 같은 묶음의 다른 화면 | 그 묶음의 첫 탭 | 그 탭으로 간다 |
| 그 밖의 화면 | 더보기 | 더보기의 그 묶음 구획을 연다 |

공통 묶음은 탭에 알림이 있어도 묶음으로 치지 않는다. 일정, 공지와 자료실, 내 정보에서는 더보기가 켜진다. 꺼진 모듈의 항목은 사이드바, 탭, 더보기에서 모두 빠진다. 모듈은 `09_기능기획서.md` 1.1 이다.

| 알약 | 규칙 아래 조직은 본부, 지점이다. 시작 조직 자체는 알약이 없다. 조직장 이름도 계층 이름을 따른다(본부장, 지점장) |
| 시작 조직 | 규칙에 start 가 있으면 그 위쪽 조직은 선택 상자, 조직 트리, 경로 줄, 맨 위 조직부터 단추에서 숨는다. 주소로 직접 열어도 guard 의 권한과 범위 검사는 그대로다 |
| 선택 상자 | 글에 본부 이름이 앞에 붙는다(예: H본부 > 직할지점). 값은 org_id 다. 같은 이름의 지점이 여러 본부 아래에 있어도 구별된다 |
| 규칙이 없을 때 | 시작 조직이 DB 에 없으면 예전 화면과 같다. org_levels.yaml 의 계층 이름과 들여쓴 이름을 쓴다 |

시험은 `tests/test_org_labels_screens.py` 다.

## 6. 인포그래픽 규칙

- 한 화면에 고리는 둘까지만 쓴다. 많으면 무엇이 중요한지 흐려진다.
- 한 줄의 숫자 카드는 휴대폰에서 셋, PC 에서 다섯을 넘기지 않는다.
- 그림에는 반드시 숫자를 함께 적는다. 색과 모양만으로 뜻을 전하지 않는다.
- 조건이 여러 개인 지급률은 숫자 하나로 줄이지 않고 원문 그대로 보여 준다.
- 금액이 가려져야 하는 화면에서는 막대도 그리지 않는다.
