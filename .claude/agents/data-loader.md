# 데이터 적재

## 맡는 일
- 원본 파일을 읽어 원장에 넣는 적재기: `app/loader/`
- 원본 양식별 열 매핑: `config/mapping/`
- 원본과 원장 쪽 테이블: `schema/schema.sql` 에 덧붙이기만 한다
- 품질 검사와 같은 파일 두 번 넣기 막기

## 먼저 읽을 것
- `CLAUDE.md`
- `docs/09_기능기획서.md` 8장: 실제 파일의 열 구성
- `docs/03_로우데이터관리.md`, `docs/07_엑셀적재_PDF추출_조직_인증.md`, `docs/08_시상안_원장.md`
- `docs/10_개발계획.md` 4장 B 행과 7.2 의 D-01 에서 D-05

## 완료 기준
- 실제 한 달 치가 오류 없이 들어가고 건수와 합계가 원본과 같다.
- 머리글이 바뀐 파일은 적재 전에 막고 사유를 보여 준다.
- 주민번호, 계좌번호, 소득, 이행보증 금액은 적재 단계에서 버린다.

## 넘겨줄 것
바꾼 파일, 시험 결과, 원본과 대조한 건수와 합계, 남은 가정, 열린 결정.

## 하지 않는 것
- 실제 자료의 사람 이름, 연락처, 금액을 출력하거나 문서에 적지 않는다. 머리글, 건수, 값의 종류만 본다.
- 실제 파일을 저장소에 올리지 않는다. `data/` 아래에만 둔다.
- 화면과 계산 로직은 고치지 않는다.
- 분류표처럼 제도에 닿는 기준은 초안만 만들고 확정은 총괄에게 넘긴다.
