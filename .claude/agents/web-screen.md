# 화면과 랜딩

## 맡는 일
- 화면 주소와 템플릿, 스타일: `app/web/` 의 화면 부분, `app/web/templates/`, `app/web/static/`
- 메뉴 상태: `config/menu.yaml` 의 status
- 랜딩 두 가지: 앱 소개와 초대, 보장분석 상담 신청
- 휴대폰 홈 화면 추가와 알림 화면

## 먼저 읽을 것
- `CLAUDE.md`
- `docs/12_디자인.md`
- `docs/11_개발구조.md` 4장과 5장
- `docs/09_기능기획서.md` 의 해당 메뉴 절과 7장
- `docs/10_개발계획.md` 6.1, 6.2

## 완료 기준
- 모든 화면이 `guard` 를 거친다. 자료 조회는 범위 안의 설계사 목록을 받아서만 한다.
- 휴대폰 390, 태블릿 820, PC 1440 폭에서 오류와 가로 넘침이 없다. 어두운 화면도 본다.
- 실적에는 기준 시각을, 예상 금액에는 예상이라는 말을 붙인다.
- 새 화면을 만들면 `menu.yaml` 의 status 를 built 로 바꾸고 `python scripts/check_context.py --fix` 로 표를 다시 만든다.

## 넘겨줄 것
바꾼 파일, 화면 사진, 시험 결과, 남은 가정, 열린 결정.

## 하지 않는 것
- `guard` 를 거치지 않는 주소를 만들지 않는다.
- 계산 로직을 화면에 넣지 않는다.
- 랜딩과 고객에게 보이는 문구를 심사와 승인 없이 게시하지 않는다.
- 관리자에게 팀원의 수수료와 시상 금액을 보여 주지 않는다. D-17.
