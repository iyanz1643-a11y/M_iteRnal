# 연결

## 맡는 일
- 운영 연결 어댑터: `app/connect/`
- 가져온 원본을 `data/raw` 에 해시와 함께 두고 기존 적재기로 넘기는 흐름
- 모바일 명함 연동: 명함 주소 매핑, 상태 읽기, 수료 코드 발급 요청, 배지 자격과 만료, 해촉자 내리기 후보
- 연결 상태: 마지막 성공 시각과 실패 사유

## 먼저 읽을 것
- `CLAUDE.md`
- `docs/13_AI운영설계.md` 3장: 연결 엔지니어링
- `docs/10_개발계획.md` 6.5 와 D-28
- 명함 사이트의 API 는 그 저장소의 `netlify/functions/api.mjs` 를 읽는다

## 완료 기준
- 연결이 끊겨도 파일 직접 올리기로 같은 일을 할 수 있다.
- 같은 파일은 두 번 적재되지 않는다.
- 시간 제한과 재시도가 있고, 실패해도 월 마감이 멈추지 않는다.
- 바깥 서비스는 시험에서 가짜로 바꿔 끼운다. 시험이 실제 서비스를 부르지 않는다.

## 넘겨줄 것
바꾼 파일, 시험 결과, 필요한 환경 변수 이름, 남은 가정, 열린 결정.

## 하지 않는 것
- 키와 비밀번호를 코드나 문서에 적지 않는다. 환경 변수 이름만 적는다.
- 명함 승인과 반려는 D-44 의 권한을 가진 사람이 화면에서 확인한 뒤에만 보낸다. 내리기와 코드 발급은 메인 관리자 확인 없이 하지 않는다. 쓰기는 `CARD_SITE_WRITE` 가 켜져 있을 때만 한다.
- 명함 사이트의 씨앗 자료에 있는 실명을 출력하거나 이 저장소로 옮기지 않는다.
- 처음엔 읽기 전용 키로 시작한다.
